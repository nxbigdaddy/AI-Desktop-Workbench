## 1. 产品愿景

构建一个公司统一治理的 AI 办公入口，使员工能够通过对话和受控 Agent 安全地完成知识检索、内容生成、文件处理、数据查询、报表制作、邮件辅助和跨系统工作流，同时让公司具备统一身份、模型、权限、额度、插件、审计和客户端版本控制能力。

## 2. 产品目标

### 2.1 业务目标

- 降低员工寻找知识、整理材料和处理重复办公任务的时间；
- 将公司模型、知识库和内部系统能力集中到一个受控入口；
- 避免员工自行保存供应商密钥、使用未经批准的公网工具或复制敏感数据；
- 对模型调用和企业系统访问实现可归属、可计量、可审计；
- 建立可持续扩展的插件和连接器平台，而不是一次性聊天工具。

### 2.2 MVP 成功标准

MVP 必须证明三个端到端闭环：

1. 企业微信扫码登录 → 授权模型对话 → 后台看到用户级准确用量；
2. 选择三份本地 Excel → Agent 生成分析和 PPT 草稿 → 全过程可确认、可恢复、可审计；
3. 上传文件到个人 MaxKB 知识库 → 查看处理状态 → 带引用问答。

### 2.3 不以 MVP 证明的内容

- 无人监督的全自动办公；
- 任意生产数据库自然语言写入；
- 同时支持 Windows、macOS 和 Linux；
- 开放第三方插件市场；
- 替代现有模型代理、MaxKB、邮件系统或业务系统。

## 3. 用户与角色

### 3.1 普通员工

目标：快速对话、处理文件、查询被授权数据、生成可信制品。

痛点：工具分散、模型选择困难、文件反复复制、输出缺少来源、复杂任务失败后需要重来。

### 3.2 部门负责人

目标：汇总周报/月报、生成经营简报、查看部门 AI 使用和预算。

痛点：数据口径不一致、汇报材料重复制作、无法判断 AI 结果是否可靠。

### 3.3 系统/数据负责人

目标：以 API、语义数据集或 MCP 工具安全开放业务能力。

痛点：担心模型越权、SQL 失控、接口被滥用和缺少审计。

### 3.4 AI/模型管理员

目标：维护模型目录、能力、路由、额度、成本和降级策略。

### 3.5 插件/连接器管理员

目标：发布、审批、灰度、分配、撤回插件和连接器。

### 3.6 安全与审计员

目标：查看登录、模型、文件、工具、数据查询、审批、导出和更新历史。

### 3.7 平台运维人员

目标：维护服务健康、客户端版本、任务队列、模型调用和连接器可用性。

## 5. 核心用户旅程

### 5.1 首次登录

1. 用户启动客户端；
2. 客户端向后台创建登录事务；
3. 显示企业微信二维码；
4. 用户扫码并确认；
5. 后台取得企业身份并映射用户、部门、角色和设备；
6. 客户端取得短期访问令牌及可续期会话；
7. 客户端加载模型、插件、策略和版本要求；
8. 进入首页或 AI 对话。

失败分支：二维码过期、用户不在企业、账号禁用、应用未授权、设备不合规、回调超时、后台不可用。

### 5.2 普通 AI 对话

1. 用户新建会话；
2. 选择逻辑模型，或使用管理员推荐模型；
3. 输入文本或添加附件；
4. 客户端展示数据边界和允许工具；
5. 后台执行权限与额度预检；
6. AI 流式回复；
7. 展示引用、实际工具状态、用量和错误；
8. 用户复制、导出、反馈或升级为任务。

### 5.3 本地文件 Agent

1. 用户选择本地工作区或具体文件；
2. 描述任务目标和输出格式；
3. Agent 生成可读计划；
4. 客户端展示文件范围、工具、数据去向和危险动作；
5. 用户确认执行；
6. 执行器逐步执行并持续记录事件；
7. 需要覆盖、删除、上传或外发时再次确认；
8. 失败时用户重试、修改、跳过或人工接管；
9. 生成制品并验证；
10. 用户预览并决定保存、提交或废弃。

### 5.4 MaxKB 个人知识库

1. 用户查看有权访问的知识库；
2. 创建个人知识库或选择已有知识库；
3. 选择本地文件并确认上传目标；
4. 后台连接器上传文件；
5. 客户端轮询/订阅解析状态；
6. 成功后发起问答；
7. 回复展示引用、文档和片段；
8. 用户可查看原文或报告错误。

### 5.5 内部系统自然语言查询

1. 用户选择企业应用或在对话中提出问题；
2. 系统识别合适的连接器和数据集；
3. 展示指标口径、数据时间和用户权限范围；
4. 生成受控查询计划；
5. 连接器执行 API/语义查询；
6. AI 解释结果并生成表格/图表；
7. 输出附数据来源、条件、口径和刷新时间；
8. 导出大数据量时按策略审批。

## 7. 非功能需求

### 7.1 性能

| 编号 | 指标目标 |
|---|---|
| NFR-PERF-001 | 客户端冷启动 P95 ≤ 5 秒（公司标准终端，不含自动更新） |
| NFR-PERF-002 | 登录后策略与首页加载 P95 ≤ 3 秒（内网正常条件） |
| NFR-PERF-003 | AI 访问服务额外开销 P95 ≤ 200 ms，不含模型耗时 |
| NFR-PERF-004 | 流式首字节在上游返回后 200 ms 内转发 |
| NFR-PERF-005 | 管理后台常用列表 P95 ≤ 2 秒，默认分页 ≤ 50 行 |
| NFR-PERF-006 | 审计搜索按常用索引范围 P95 ≤ 5 秒 |

指标值需在阶段 0 用公司网络和终端校准。

### 7.2 可用性与可靠性

| 编号 | 要求 |
|---|---|
| NFR-REL-001 | 服务端核心 API 月可用性目标不低于 99.9% |
| NFR-REL-002 | 客户端崩溃不应破坏已落盘任务事件和制品 |
| NFR-REL-003 | 云端长任务不因客户端断线自动终止 |
| NFR-REL-004 | 写请求具备幂等键，重试不能重复创建任务或重复扣费 |
| NFR-REL-005 | 模型、连接器和插件失败相互隔离 |

### 7.3 安全

| 编号 | 要求 |
|---|---|

### 7.4 可维护性

- 模块拥有自己的数据和应用服务边界；
- 对外 API 版本化；
- 模型、连接器和执行引擎使用适配器；
- 关键策略可配置但有安全默认值；
- 数据迁移可重复执行并在 MySQL 环境持续测试；
- 关键领域逻辑具备单元测试和契约测试。

### 7.5 可访问性与桌面兼容

- 支持 Windows 系统缩放和高 DPI；
- 关键操作可键盘完成；
- 状态不只依赖颜色；
- 支持中文字体回退；
- 弹窗、任务和错误具备屏幕阅读器可理解的标签；
- 最低 Windows 版本由公司终端基线确定。

## 8. 数据分类

| 等级 | 示例 | 默认策略 |
|---|---|---|
| L0 公开 | 公开宣传材料 | 可使用被批准的外部模型 |
| L1 内部 | 一般制度、内部通知 | 仅公司批准的处理边界 |
| L2 敏感 | 经营数据、客户信息、员工信息 | 指定模型、脱敏、严格审计 |
| L3 高敏 | 财务明细、密钥、身份凭据、受限个人信息 | 默认禁止进入通用模型；专用流程审批 |

最终等级名称和规则应与公司现行制度对齐。

## 9. 产品指标

### 9.1 使用指标

- 周活跃用户、月活跃用户；
- 新用户次日/七日留存；
- 每用户有效会话和任务数；
- Skill、知识库和企业连接器采用率。

### 9.2 效率指标

- 任务完成率和平均完成时长；
- 文件制品一次验收通过率；
- 失败后恢复成功率；
- 用户估算节省时间（抽样）。

### 9.3 质量与信任

- 有引用回答比例；
- 数据报表口径错误率；
- 用户反馈有用率；
- 危险操作撤销率、误发和数据越权事件数；
- 未经确认的写操作必须为 0。

### 9.4 成本

- 每活跃用户模型成本；
- 每成功任务成本；
- 按模型/部门/模块的预算偏差；
- 低成本模型降级后的质量变化。

## 10. 验收边界

MVP 不是“页面能打开”即完成。每个核心闭环必须同时满足：

- 正常路径可用；
- 至少三个主要失败分支有明确恢复；
- 权限被服务端强制执行；
- 用量和审计可追踪到用户与请求；
- 客户端重启或断网不丢失需要保留的状态；
- 输出文件经过结构与可打开性验证；
- 管理员可撤销用户、插件、连接器或客户端版本的使用权。
